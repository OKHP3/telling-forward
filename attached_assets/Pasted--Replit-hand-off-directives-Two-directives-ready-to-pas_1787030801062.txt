## Directive 1: Wire the ingestion trigger into the Author App

```
Add an endpoint that lets the Author App kick off manuscript ingestion for
a storyworld.

Context: .github/workflows/manuscript-ingestion.yml (already in the repo)
runs the ingestion pipeline via a workflow_dispatch event, taking
manuscript_path, owner, and repo as inputs. Right now nothing in the app
triggers that event — it's a placeholder pending this wiring.

Add a new route, following the existing pattern in
artifacts/api-server/src/routes/storyworlds.ts and transcribe.ts (Zod
request validation via @workspace/api-zod, requireAuth middleware,
pino request logging via req.log). Suggested location:
artifacts/api-server/src/routes/ingestion.ts, registered in
artifacts/api-server/src/routes/index.ts alongside the others.

The route should:
1. Accept an uploaded manuscript file (DOCX, EPUB, or PDF) for a given
   storyworld ID, similar to how transcribe.ts accepts base64 audio —
   check whether storyworld uploads already have a place to land (an
   `intake/` path in the storyworld repo, or similar) before inventing a
   new one.
2. Commit that file into the storyworld's GitHub repo using the existing
   GitHubClientInterface's createCommit (see
   artifacts/api-server/src/lib/github.ts) rather than a new GitHub client.
3. Trigger the manuscript-ingestion.yml workflow via GitHub's "create a
   workflow dispatch event" API
   (octokit.rest.actions.createWorkflowDispatch), passing the committed
   file's path plus the storyworld's owner/repo. Note:
   GitHubClientInterface doesn't have a method for this yet — add one
   (createWorkflowDispatch or similar) rather than reaching into Octokit
   directly from the route handler, to keep the existing
   "route handlers never touch the token directly" boundary intact.
4. Return a response the Author App UI can poll or otherwise use to tell
   the contributor "your manuscript is being processed" rather than
   claiming synchronous completion — this is an async pipeline, minutes
   not seconds.

Do not build any UI for this yet unless it's trivial to wire to something
that already exists. Focus on the endpoint and the GitHub client method.
Run pnpm run typecheck and pnpm run build before finishing, per AGENTS.md's
safe change procedure.
```

## Directive 2: Concept Board live-preview (in-browser model tier)

```
Investigate first, then implement if it's a reasonable fit.

Look at the current state of artifacts/web (or wherever the Concept Board
UI actually lives — confirm the path first, don't assume). Report back
what framework it's built on and whether it already has any kind of
live-suggestion or AI-assist surface before writing code.

The feature to add: an optional, capability-detected live preview that
runs Phi-4-mini-instruct client-side via transformers.js and WebGPU
(published web-ready build: webnn/Phi-4-mini-instruct-onnx-transformers_js
on Hugging Face) while a contributor is typing or has just uploaded a
short passage into Concept Board. This is a progressive enhancement, not
a required feature — it should never block or replace the
GitHub-Actions-based ingestion tier that already exists
(.github/workflows/manuscript-ingestion.yml), which remains the tier that
actually serves phone/low-end-device contributors.

Requirements if you proceed:
1. Feature-detect WebGPU support on load. If unavailable (Safari/iOS gaps
   are common), the live-preview UI element should not appear at all —
   no broken button, no error state a user has to dismiss.
2. Model download is several hundred MB to a few GB depending on
   quantization — this needs an explicit user opt-in (a button, not
   automatic on page load) and clear messaging about the download size
   before it starts.
3. Whatever this surfaces (candidate capsule suggestions) should route
   through the same draft-capsule creation path as every other tier —
   labeled capsule + state:draft, never auto-promoted. Check whether that
   path exists yet server-side (as of 2026-08-18 it does not — see
   docs/adr/0004-manuscript-ingestion-and-bring-your-own-ai.md) before
   assuming there's an endpoint to call.

If the investigation turns up that artifacts/web doesn't have an obvious
place for this yet, or that Concept Board itself isn't built yet, stop
and report that back rather than scaffolding a feature with nothing real
to attach it to.
```
