| Option | What it is | Effort | Fit here |
|---|---|---|---|
| Fork [github-markdown-css](https://github.com/sindresorhus/github-markdown-css) | MIT stylesheet replicating GitHub's own README rendering, still active (v5.1.0 on npm/jsDelivr) | Low — drop in, retheme per reader skin | Best match to "on-brand, GitHub's own visual language" — re-skin its CSS variables per theme (Editorial, Terminal, Archive, Dispatch, Transmission) instead of writing typography rules from scratch |
| Tailwind `@tailwindcss/typography` (`prose` classes) | Official Tailwind plugin for styled markdown output, already installed in the Author App's `package.json` | Low-medium — confirm it's added to the Reader App too, then theme via CSS variables per skin | Most idiomatic given the stack (Tailwind + shadcn already everywhere); less "GitHub flavor," more "your own design system" |
| Swap to [react-markdown](https://github.com/remarkjs/react-markdown) + `remark-gfm` | Full remark/rehype pipeline, per-node-type custom React components | Higher — replaces `marked`, not additive | Only worth it if you want per-element custom rendering (e.g. a capsule reference rendered as a styled chip). | GitHub's actual engine, `cmark-gfm` | The C library behind github.com's own rendering | Not practical | Skip — it's what `github-markdown-css` is already reverse-engineered from |

**Recommendation:** don't touch `marked`/`DOMPurify`, they're doing their job. Fork `github-markdown-css` as the base, and either apply it directly with theme-specific CSS variable overrides per reader skin, or blend it with `@tailwindcss/typography` if you want the Reader App fully inside your existing design-token system rather than importing GitHub's variable names. Either way this is a styling task, not a rendering-engine task, which is a much smaller lift than it sounded like walking in.
